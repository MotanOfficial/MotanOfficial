### Shared S3rpent infrastructure

The S3rpent applications are designed around shared services rather than completely isolated account systems.

**Centralized architecture:**

- **Supabase Auth:** Shared authentication and user accounts across connected S3rpent applications.
- **Supabase Edge Functions:** Server-side operations and controlled access to private update resources.
- **Private GitHub repositories:** Hosting application updates.
- **Shared identity:** One account system across participating applications.

S3rpent Media currently operates outside this shared authentication and update infrastructure.

<!-- ==================== ENGINEERING PHILOSOPHY ==================== -->

<h2>
  <img src="https://api.iconify.design/lucide/brain-circuit.svg?color=%23EF4444" width="23" align="absmiddle" alt=""/>
  &nbsp; Engineering Philosophy
</h2>

I believe good software is more than a collection of features.

I care about how an application feels to use, how efficiently it runs, how securely it handles information and how well its architecture supports future development.

My approach is guided by a few principles:

- **Understand the system:** Learn how components communicate instead of treating frameworks as magic.
- **Build with purpose:** Avoid unnecessary complexity and dependencies.
- **Respect resources:** Performance and memory usage matter.
- **Design for people:** Good software should be intuitive and enjoyable to use.
- **Think about security:** Privacy and security belong in the engineering process.
- **Connect the pieces:** Applications, services and infrastructure should work together.
